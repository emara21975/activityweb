# خطة تنفيذ نسخة الويب — 3 مراحل

> الإصدار: 2.0 — 2026-09-24 | الحالة: مواصفات تنفيذ معتمدة | النطاق: مدرسة واحدة، مستخدمون متعددون، VPS، قاعدة جديدة فارغة.
> هذه الوثيقة تحل محل النسخة المكتبية المقابلة. لا تنطبق أي تعليمات تخص PySide6 أو SQLite أو Portable EXE أو التشغيل دون إنترنت على نسخة الويب.

## المنهج
تنفيذ دورة عمل رأسية مبكرًا: طالب → نشاط → مشاركة → تقرير طالب/نشاط → إحصائيات. ثلاث مراحل مع بوابات قبول، دون تعقيد Enterprise أو نشر نسخة مكتبية. لا يبدأ الإنتاج ببيانات الطلاب أو الأنشطة القديمة.

## المرحلة 1 — الأساس + دورة العمل + الدخول
1. إنشاء Next.js App Router/TypeScript وTailwind وshadcn/ui وإعداد ESLint/typecheck/tests وملف env.example بلا أسرار.
2. PostgreSQL + Prisma schema/migrations للجداول الأساسية والأذون؛ seed للتصنيفات والأدوار والأذون فقط؛ bootstrap آمن لأول مدير.
3. جلسات ودخول وخروج وحماية الطلبات وإدارة المستخدمين الأساسية وRBAC خادمي واختبارات منع الوصول المباشر.
4. إعداد المدرسة والسنة والصفوف والشعب؛ إدارة الطلاب وتسجيلاتهم، الأنشطة، المشاركات الجماعية بمعاملة وUNIQUE.
5. Dashboard أولية وإطار RTL responsive وسجل تدقيق للتعديلات.
**بوابة 1:** مدير ينشئ مستخدمًا محدودًا؛ المستخدم ينشئ طالبًا/نشاطًا ويسجل مشاركة حسب الإذن؛ بعد الخروج والدخول تبقى البيانات؛ محاولة التكرار والطلب غير المصرح مرفوضان.

## المرحلة 2 — التقارير والإحصائيات وExcel
1. ملفات الطلاب (stu)، الأنشطة (act)، الفئات (kind)، الصفوف والشعب، المشاركين وغير المشاركين، الجنسية والفترة.
2. StatisticsService موحدة مع Population والتواريخ والتصنيفات والتفصيل drill-down.
3. التقرير الرسمي (stat/النسب) ومطابقة الأرقام بين Dashboard/التقارير.
4. PDF عربي RTL وطباعة وExcel XLSX من نفس dataset؛ تنزيلات مصرح بها.
5. قوالب Excel ورفع/تطبيع/تحقق/معاينة/اعتماد اختياري لطلاب/أنشطة/مشاركات؛ لا استيراد تلقائي لبيانات قديمة.
**بوابة 2:** سيناريوهات الطالب الفريد/المشاركات، صفر مقام، التاريخ، الجنسية المجهولة، وفلاتر الصف/الشعبة؛ تطابق الأرقام في العرض/PDF/XLSX؛ رفض التصدير بلا إذن.

## المرحلة 3 — المرفقات والحماية والنشر
1. مرفقات خاصة وتنزيل محمي وحدود نوع/حجم ومكافحة traversal، أرشفة وتنظيف آمن.
2. إدارة الأدوار والصلاحيات الكاملة، تدقيق، منع تعطيل آخر مدير، حماية الجلسات وrate limiting وفحص الوصول لكل route/action.
3. نسخ PostgreSQL + مرفقات وmetadata وجدولة واحتفاظ وفحص استعادة تجريبية؛ استعادة إنتاج بإذن وتأكيد ونقطة رجوع.
4. مراجعة responsive/RTL/accessibility، أداء وفهارس، pagination، سجلات ومراقبة، اختبارات E2E، إعداد Nginx/TLS/systemd وCI وخطة rollback.
**بوابة 3:** نجاح smoke tests على staging، restore drill، اختبار حسابات متعددة متزامنة، عدم انكشاف DB/المرفقات، اختبار تحديث migration دون فقد البيانات، ثم نشر الإنتاج الفارغ.

## مصفوفة اختبارات إلزامية
| المجال | التحقق |
|---|---|
| الهوية | لا يتكرر الرقم الأكاديمي؛ انتقال الصف لا يكرر الطالب |
| المشاركات | UNIQUE + transaction + سباق مستخدمين |
| الإحصائيات | DISTINCT مقابل COUNT؛ Population؛ الصفر؛ الفلاتر؛ السنوات |
| الأذون | GET/POST/Action/Download/Export/Restore غير مصرح = منع خادمي |
| الملفات | MIME/حجم/اسم آمن، لا public URL، فحص إذن التنزيل |
| التقارير | نفس dataset في UI/PDF/XLSX، عربية RTL |
| التشغيل | restart/redeploy/migrate/backup/restore بلا فقد بيانات |

## تعريف الإنجاز
الكود والاختبارات والمهاجرات وREADME وأوامر التشغيل والنشر موجودة في المستودع؛ لا توجد أسرار أو بيانات طلاب تجريبية في الإنتاج؛ الوظائف الأصلية تعمل عبر المتصفح؛ كل صلاحية مفحوصة خادميًا؛ يستطيع مدير المدرسة استخدام النظام بعد إعداد أولي آمن.
