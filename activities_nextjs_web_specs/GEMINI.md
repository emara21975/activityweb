# تعليمات وكيل التطوير — Antigravity / Gemini / Cursor

> الإصدار: 2.0 — 2026-09-24 | الحالة: مواصفات تنفيذ معتمدة | النطاق: مدرسة واحدة، مستخدمون متعددون، VPS، قاعدة جديدة فارغة.
> هذه الوثيقة تحل محل النسخة المكتبية المقابلة. لا تنطبق أي تعليمات تخص PySide6 أو SQLite أو Portable EXE أو التشغيل دون إنترنت على نسخة الويب.

## المهمة والحدود
نفّذ تطبيق إدارة الأنشطة الطلابية Web Fullstack Next.js لمدرسة واحدة وعدة مستخدمين وصلاحيات على VPS، بقاعدة PostgreSQL جديدة وفارغة. هذه وثيقة تنفيذ وليست تعليمات لبناء Portable EXE. لا تضف multi-tenancy أو تطبيق موبايل أصلي أو مزامنة offline أو خدمات مصغرة أو وسيط AI دون طلب.

## ترتيب مصادر الحقيقة
`PRD.md` للوظائف، `BUSINESS_RULES.md` للحسابات، `DATABASE_SCHEMA.md` للبيانات، `TECHNICAL_STACK.md` للمعمارية والأمان، `UI_UX_SPECIFICATION.md` للواجهة، `IMPLEMENTATION_ROADMAP.md` للترتيب، وهذه الوثيقة لسلوك الوكيل. إذا تعارضت الوثائق أبلغ عن التعارض الحقيقي قبل قرار يغير وظيفة أو سلامة بيانات؛ لا ترجع لنسخ Desktop القديمة.

## قواعد التنفيذ
1. اقرأ الملفات الثمانية قبل بدء التطوير، ثم افحص الملفات الموجودة قبل تعديلها؛ نفذ أصغر تغيير متماسك مع اختباراته.
2. استخدم Next.js App Router/TypeScript strict وPostgreSQL/Prisma وواجهة عربية RTL؛ ثبّت نسخ الحزم في lockfile؛ لا تنشئ API خارجيًا عامًا بلا حاجة.
3. ابدأ بتوثيق schema ومصفوفة الأذون ثم migrations وseed الآمن. لا تُنشئ طلابًا أو أنشطة أو مشاركات تجريبية في production؛ لا تستخدم `db push` لتعديل production.
4. لا تضع Business Logic في React أو PDF/Excel. اجعل `StatisticsService` و`ReportService` مصدرًا واحدًا للأرقام.
5. افحص الجلسة والإذن على الخادم داخل كل Server Action وRoute Handler وخدمة حساسة، وكذلك على مستوى السجل. إخفاء الزر لا يكفي. لا تقبل هوية الفاعل من payload.
6. استخدم Zod لمدخلات الخادم، معاملات DB للحفظ الجماعي، unique constraints للتكرار، وسجل تدقيق بعد حجب الأسرار.
7. المرفقات خارج public، وروابط التنزيل تمر عبر authorization؛ لا تضع بيانات حساسة في URL أو log؛ الأسرار في env غير متعقب.
8. لا تستبدل تعريفات Population وDISTINCT/COUNT ولا تُخمن الجنسية أو أرقام الطلاب؛ لا تخلط سنوات أكاديمية.
9. راعِ السباق بين المستخدمين، إعادة تحميل البيانات بعد التعديل، pagination على الخادم، وأخطاء عربية مفهومة دون stack traces.
10. لا تعلن اكتمال ميزة دون اختبار نجاح وفشل وصلاحياتها. شغّل lint/typecheck/unit/integration/E2E ذات الصلة وسجل النتائج الحقيقية، ولا تدّعِ اختبارًا لم يُنفذ.

## بروتوكول كل مهمة
افهم المتطلب والملفات ذات الصلة → حدد المخطط/الإذن/الخدمة/الواجهة/الاختبارات المتأثرة → نفذ migration آمنة إن لزم → نفذ الخدمة والواجهة → اختبر المستخدم المصرح وغير المصرح والتزامن → لخص الملفات المتغيرة والأوامر والنتائج والمخاطر المتبقية. لا تغيّر تقنية أو نطاقًا معتمدًا من تلقاء نفسك.
